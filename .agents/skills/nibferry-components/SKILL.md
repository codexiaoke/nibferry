# Nibferry 组件规范

用户要求讨论设计、调研或查看现状时，交付讨论结果。讨论中的目录名、部件和 API 属于候选方案；用户要求实现时，再按已确认的范围修改代码。

## 模块、组件与 README

- Nibferry 是通用 React UI 组件库。按输入、选择、折叠、导航、反馈等 UI 能力划分模块。规范、Token 命名和基础示例用组件自身的交互说明，具体业务流程只出现在明确的场景示例中。设计部件时写清它接收的数据、触发的事件和状态归属，需要父组件配合时说明组合关系。
- 库组件一律位于 `packages/react/src/components/<能力模块>/<组件名>/`。一个组件一个目录，公开的小部件和组合组件都遵守。主实现与目录同名；专属样式、交互测试就近存放。只为实际存在的样式、类型和逻辑建文件。
- **每个组件目录必须有自己的 `README.md`**。至少给出组件职责、从公开入口导入的最小用例、Props 与回调。按实际能力补充状态归属、依赖的父组件、可替换部件、主题变量、键盘与焦点行为。官网示例不能代替组件 README；改动公开行为时同步更新它。

## 控件外观与图标

- **禁止使用浏览器或操作系统的默认控件外观。** 保留适合的 HTML 语义、表单行为和键盘能力；可见的按钮、输入框、选择器、复选框、滑杆及其交互状态统一使用 Nibferry 样式。例如复选框保留可聚焦的 `input`、关联的标签和空格切换行为，方框与选中标记由组件绘制。只改 `accent-color` 仍会留下平台控件造型。
- **界面图标统一使用项目使用的 Hugeicons 线性 SVG。** 禁止把浏览器自带箭头、系统图标、图标字体、Unicode 字符或 Emoji 当图标。按钮中的关闭、返回、展开、选中等标记都从图标库取；纯图标按钮提供准确的无障碍名称，装饰 SVG 对读屏隐藏。
- 产品编写的标题、按钮、状态、提示和示例文案均禁用 Emoji 装饰。用户输入和导入的原文按原样呈现。
- 设计或评审主题与组件外观时，读取仓库的 [UI Token 规范](../../../docs/design-tokens.md)。全局视觉角色、浅深配色和组件覆盖以该文档为准。使用已实现的接口时对照当前包的导出与类型。

## 文案与验收

- 涉及可见文案时，必须同时读取并执行 [frontend-ui-copy](/Users/xiaoke/.codex/skills/frontend-ui-copy/SKILL.md)。中文标题直接写内容，按钮写动作，说明只保留对理解状态、选择或操作有帮助的信息；保留表单标签和无障碍名称。
- 在实际涉及的状态下看渲染结果，重点检查容易残留的平台箭头、复选标记和滑杆手柄。用键盘走通改动的交互，检查本次涉及的焦点、主题和减少动效行为。
- 交付前对照组件 README 中的公开用例、实际导出和交互结果；评审发现偏差时，指出具体组件、文件和违反的条款。
