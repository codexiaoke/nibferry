# Nibferry Git 操作规范

## 组织提交

- 先用 `git status --short --branch`、`git diff` 和 `git diff --cached` 区分已有暂存内容与本次改动。只暂存本次需要的文件或代码块。
- 每个提交完成一个可单独评审和回退的改动。实现、对应测试和必要的文档一起提交。独立的功能、清理或维护规则分开提交。
- 提交说明遵循仓库的[贡献指南](../../../CONTRIBUTING.md)。一行简短英文，动词原形开头，直接写改变了什么，例如 `Remove prototype components`。
- 提交前核对暂存差异，运行与改动相关的检查。公开 API 有变化时同步核对导出、接入文档和 Changeset。

## 分支与推送

- 协作改动从最新的目标分支创建短期工作分支，通过 PR 合入。首次推送空仓库可将当前主分支设为上游。已有分支遵循仓库保护规则。
- 推送前核对远端 URL、目标分支和待推送的提交。遇到非快进拒绝，先 fetch 并比较双方历史，保留远端已有提交后再推送。改写共享历史需要单独授权。
- 推送完成后，比较本地提交与远端目标引用的 SHA，再报告分支、提交或 PR 链接。区分“已推送分支”和“已合入主分支”。
