## 产品范围

Nibferry 面向构建 Agent 产品的 React 团队。Agent 可以是产品的主界面，也可以作为侧边或悬浮助手嵌入已有页面。三种形态共用输入、消息、引用和操作等部件。本文记录设计与验收约定，文中的部件名称用于说明职责。

## 公开部件如何拆分

官方默认组合必须能用公开部件搭出。在不同形态中需要独立移动、替换或省略的部分，应当向使用方开放。例如附件列表、单个附件和移除操作可以分别取用；文件名的字号和颜色由排版与主题 Token 控制。

使用方可以重排操作，或换成产品已有的控件，同时沿用可用状态、键盘操作和回调。例如同一项审批在完整对话里可以平铺操作，在窄侧栏里可以把次要操作移入菜单。两处都从同一份审批状态判断用户能否继续操作。

库组件按输入、选择、导航、反馈等 UI 能力归档，路径为 `packages/react/src/components/<能力模块>/<组件名>/`。公开部件和默认组合各有自己的目录和 `README.md`。README 给出职责、公开导入的最小用例、参数与回调，并按组件实际能力说明父级依赖、状态归属、可替换部件、主题变量和键盘焦点行为。

控件保留语义和键盘行为，外观由 Nibferry 统一绘制，操作图标使用 Hugeicons 线性 SVG。配色、密度和动效分别配置。视觉角色与覆盖规则见[设计 Token](/docs/theme)。

## 状态归属

| 范围 | 约定 |
| --- | --- |
| 展示部件 | 传入数据即可呈现。摘要条目通过回调报告用户选中的文件，同一个条目也能用于消息或来源列表。 |
| 组合内的交互 | 相关部件可以依赖最近的组合容器。例如分支切换器需要当前回复的分支状态。README 写明这项依赖，以便使用方单独接入。 |
| 产品数据与动作 | 消息、草稿、Agent 运行和审批结果由接入产品持有。产品决定选中的文件是在桌面的工作区标签中打开，还是在手机上单独阅读。 |
| 分栏宽度 | 分栏默认处理拖动、键盘调宽和全屏还原。产品需要保存布局时，可以从外部读取和设置宽度。 |

## 对话首页

新会话与进行中的会话共用同一个输入器。发出第一条消息后，消息区成为主要阅读区域，输入器位于对话栏底部。布局切换保留草稿、已选模型和待发送附件。

产品导航与会话历史可分别使用。消息区、输入器和右侧工作区也可独立组合。在已有产品页面旁嵌入助手时，可以只取消息区和输入器，继续使用宿主页面的导航。

## 摘要、分栏与全屏

桌面窗口的控件、主标题和右栏标签共用一行。并排时，主标题区止于两栏的分隔线，右栏标签从分隔线另一侧开始排列。拖动分栏和切换全屏时，标题区与下方内容的边界同步移动。

桌面首页有三个可以分别控制的部分。摘要属于主区域，右侧工作区承载打开的内容，全屏时浮动对话承载当前会话。

| 用户操作 | 桌面行为 |
| --- | --- |
| 查看摘要 | 窗口工具栏的摘要按钮切换主区域右上角的卡片。即使右栏收起，用户也能查看摘要。摘要的分组、条目和点击行为由接入产品提供。 |
| 打开右侧工作区 | 工具栏的右栏按钮展开分栏。产品也可以让摘要条目直接打开对应内容。对话与内容并排可操作，分隔线支持拖动和键盘调宽。收起右栏后，摘要按用户先前的选择显示。 |
| 将右侧内容全屏 | 当前标签占满左侧导航以外的内容区。左侧导航沿用用户的展开或收起状态，当前对话以浮窗呈现，底下的内容仍可操作。 |
| 收起浮动对话 | 点击浮窗标题栏的收起按钮，工作区右下角出现聊天入口。用户可以继续操作当前全屏内容。 |
| 从右下角恢复对话 | 点击聊天入口，在当前内容上方恢复同一会话的消息、草稿和待发送附件。文档停在原来的阅读位置。 |
| 退出工作区全屏 | 顶部的退出全屏按钮恢复并排布局和原栏宽。当前标签继续显示，对话回到主区域。 |

### 部件与控制方式

下表列出组件设计使用的名称。现有组件的导入方式和参数见[基础布局组件](/docs/layout)和[摘要面板](/docs/summary)。

| 部件 | 组合位置与职责 |
| --- | --- |
| `SummaryCard`、`SummaryGroup`、`SummaryItem`、`SummaryToggle` | 卡片放在 `MainPane` 中，分组和条目按需组合。条目报告用户选中了哪一项，由产品决定打开位置。摘要开关可以放在卡片外的窗口工具栏。 |
| `RightPane`、`PaneResizeHandle` | 复用现有布局部件。右栏容纳产品提供的内容，分隔线负责调宽。产品可分别组合标签栏、标签项、面板操作和内容视图。 |
| `RightPaneToggle`、`RightPaneFullscreenToggle` | 两个独立操作分别控制展开与收起、全屏与还原。使用方可以把它们放进自己的工具栏，也可以用自己的按钮驱动相同的布局状态。 |
| `FloatingPanel`、`FloatingPanelTrigger` | 浮层提供标题栏和内容区域，标题栏可放收起按钮。浮层与恢复入口可分别放置。官方组合将恢复入口放在右下角，将当前会话的消息和输入器放进浮层。 |

接入产品可分别控制摘要显隐、右栏模式（收起、并排、全屏）和全屏时的对话浮窗显隐。右栏模式决定空间分配，当前标签和会话数据由产品持有。分栏对话和浮动对话读写同一份草稿与附件。键盘收起浮窗后，焦点回到右下角的聊天入口。从该入口恢复时，焦点返回浮窗。

拖动分隔线时，边界直接跟随指针，消息正文和输入工具栏按对话栏的实际宽度适配。展开和收起使用主题过渡。系统开启减少动态效果时直接呈现目标状态。窄屏优先呈现当前对话，打开内容后单独阅读。切换布局或返回时，保留对话阅读位置、输入草稿和已打开的内容。

## 验收

- 只用公开部件还原默认组合，再把一个操作从正文移到侧栏，验证键盘行为、可用状态和回调仍然一致。
- 在已有页面中分别以侧边和悬浮方式接入同一组消息与输入部件，沿用产品自己的数据和导航。
- 在右栏收起时单独切换摘要，再从摘要打开内容。调宽右栏，输入草稿并添加附件，然后全屏、收起浮窗、从右下角恢复。核对焦点、草稿、附件和两边的阅读位置。
- 退出全屏时核对左侧导航状态、原分栏宽度和当前标签。收起右栏后核对摘要的显隐选择。窄屏下走一遍单独阅读与返回。
