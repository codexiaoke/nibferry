## 产品范围

Nibferry 面向构建 Agent 产品的 React 团队。Agent 可以是产品的主界面，也可以作为侧边或悬浮助手嵌入已有页面。三种形态共用输入、消息、引用和操作等部件。本文记录设计与验收约定，文中的部件名称用于说明职责。

## 公开部件如何拆分

官方默认组合必须能用公开部件搭出。在不同形态中需要独立移动、替换或省略的部分，应当向使用方开放。例如附件列表、单个附件和移除操作可以分别取用；文件名的字号和颜色由排版与主题 Token 控制。

使用方可以重排操作，或换成产品已有的控件，同时沿用可用状态、键盘操作和回调。例如同一项审批在完整对话里可以平铺操作，在窄侧栏里可以把次要操作移入菜单。两处都从同一份审批状态判断用户能否继续操作。

库组件按输入、选择、导航、反馈等 UI 能力归档，路径为 `packages/react/src/components/<能力模块>/<组件名>/`。公开部件和默认组合各有自己的目录和 `README.md`。README 给出职责、公开导入的最小用例、参数与回调，并按组件实际能力说明父级依赖、状态归属、可替换部件、主题变量和键盘焦点行为。

控件保留语义和键盘行为，外观由 Nibferry 统一绘制，操作图标使用 Hugeicons 线性 SVG。配色、密度和动效分别配置。视觉角色与覆盖规则见[设计 Token](/docs/theme)。

## 状态归属

| 范围 | 约定 |
| --- | --- |
| 展示部件 | 传入数据即可呈现。摘要条目通过回调报告用户选中的文件，同一个条目也能用于消息或来源列表。 |
| 组合内的交互 | 相关部件可以依赖最近的组合容器。例如分支切换器需要当前回复的分支状态。README 写明这项依赖，以便使用方单独接入。 |
| 产品数据与动作 | 消息、草稿、Agent 运行和审批结果由接入产品持有。产品决定选中的文件是在桌面的工作区标签中打开，还是在手机上单独阅读。 |
| 分栏宽度 | 分栏默认处理拖动、键盘调宽和全屏还原。产品需要保存布局时，可以从外部读取和设置宽度。 |

## 对话首页

新会话与进行中的会话共用同一个输入器。发出第一条消息后，消息区成为主要阅读区域，输入器位于对话栏底部。布局切换保留草稿、已选模型和待发送附件。

产品导航与会话历史可分别使用。消息区、输入器和右侧工作区也可独立组合。在已有产品页面旁嵌入助手时，可以只取消息区和输入器，继续使用宿主页面的导航。

## 摘要、分栏与全屏

| 展示状态 | 工作区行为 |
| --- | --- |
| 对话与摘要 | 侧边工作区收起时，对话旁仍可查看摘要。摘要卡、分组和条目可以独立使用。变更、侧边聊天、来源是可选内容，分组及打开条目后的行为由产品决定。 |
| 并排工作 | 打开内容后，对话和工作区并排。工作区的标签栏、标签项、面板操作和内容可分别组合。分隔线支持连续拖动和键盘调宽；消息正文和输入工具栏按对话栏实际分到的宽度适配。 |
| 工作区全屏 | 当前内容占满应用工作区。退出全屏时恢复进入前的分栏宽度和活动标签。收起工作区后回到对话与摘要。 |

拖动分隔线时，边界直接跟随指针。展开和收起使用主题过渡；系统开启减少动态效果时直接呈现目标状态。窄屏优先呈现当前对话，打开内容后单独阅读。切换布局或返回时，保留对话阅读位置、输入草稿和已打开的内容。

## 验收

- 只用公开部件还原默认组合，再把一个操作从正文移到侧栏，验证键盘行为、可用状态和回调仍然一致。
- 在已有页面中分别以侧边和悬浮方式接入同一组消息与输入部件，沿用产品自己的数据和导航。
- 从摘要打开内容，调宽分栏、进入全屏、再退出并收起。核对还原的宽度、活动标签、阅读位置和草稿。窄屏下走一遍单独阅读与返回。
